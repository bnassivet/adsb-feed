# Relief: a hillshade over the base map

Status: implemented on branch `feature/sea-overlays`; not yet seen in the
running app. Last layer of phase 0
in `docs/MAP_ENGINES.md` (after airspaces, METAR, rain radar, sea).

## Source, checked 2026-11-19

Esri **World Hillshade**,
`https://server.arcgisonline.com/ArcGIS/rest/services/Elevation/World_Hillshade/MapServer/tile/{z}/{y}/{x}`:
keyless JPEG tiles, the host the dark base map already uses (same terms of
use). Real detail at z16 in the Alps and in western France (no placeholder
tiles). `World_Hillshade_Dark` exists as well.

## Blending, chosen from composites

Both hillshades are opaque, so they need a CSS blend mode. Composited in
Python on the real base tiles (OSM for light, Esri Dark Gray for dark),
60 % opacity:

| Theme | multiply, light shade | soft-light, light shade | overlay / screen / soft-light, dark shade |
|---|---|---|---|
| Light (OSM) | **clear relief, map intact** | barely visible | — |
| Dark (Esri Dark Gray) | **relief readable, map stays dark, labels kept** | brightens the whole map | darkens everything, or washes it grey |

So one source and one mode for both themes: `World_Hillshade` with
`mix-blend-mode: multiply`, on its own pane right above the base tiles
(z 250), under every data layer. White in the shade leaves the map
unchanged; only slopes darken it.

## Design

- `lib/relief.ts`: URL, attribution, default opacity (0.6), max native zoom.
- `ReliefControls` (Filters → Relief): switch and opacity, credit.
- `MapInner` `ReliefLayer`: `L.tileLayer` on the `relief` pane, the pane
  styled `mix-blend-mode: multiply`. The blend applies to the base tiles
  only, because every other pane is above it.
- Not in the tile cache (images only, HTTP cache). CSP: already allowed
  (`server.arcgisonline.com` in `img-src`); `csp.test.ts` now says so.
- localStorage: `adsb-show-relief`, `adsb-relief-opacity`.
